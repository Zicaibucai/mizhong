## 最优先

### 1. 公司介绍正文叠字 ✅

**现象**：正文 24px 字号、行高只有 22.08px，汉字上下相接，桌面与手机都挤在一起。

**根因**：正文段落误用了 `.pv-display` —— 那个类是给**超大标题**用的
（`line-height: 0.92` + 负字距 + `text-wrap: balance`）。汉字字形几乎占满 em 框，
行高低于 1 时上一行的字身会压到下一行。`quality` 区块的正文段落有同样的问题。

**修复**：新增 `.pv-lede`（`line-height: 1.75`、字距归零、`text-wrap: pretty`），
`about` 与 `quality` 两处正文/导语段落改用它。

**验证**：1440px 下实测 `font-size 24px / line-height 42px`（比值 1.75，原先 22.08px）；
375px 下 16.8px / 29.4px。

### 2. 短屏手机语言菜单不可达 ✅

**现象**：375×667 上语言菜单底部到 894px，页面被锁死不能滚动，后五种语言点不到。

**根因**：菜单面板是 `absolute top-full` 的面板，打开时 `body.overflow = hidden`
锁死页面滚动，而面板自己**没有滚动区**；面板里的语言列表又是**绝对定位的下拉框** ——
绝对定位的元素不参与滚动高度计算，即使面板能滚，列表底部仍会被面板边缘裁掉。

**修复**：面板加 `max-h-[calc(100dvh-4.25rem)] overflow-y-auto overscroll-contain`
（4.25rem 是页头高度）；`LanguageSwitcher` 新增 `inline` 变体，在手机菜单里按文档流
展开列表 —— 列表进入滚动区，跟着面板一起滚。

**验证**：375×667 实测 `scrollHeight 863 > clientHeight 598`（可滚），滚到底后最后一项
`हिन्दी` 位于 589–629px，**完整落在面板与视口内**（修复前它的顶部在 854px）。

用户继续反馈「搜品牌名搜不到」。查证结果分两层：

已补（布局里统一输出，所有公开页面都有）：

| --- | --- |

## 追加：百度站长验证（2026-09-23）

**结果：HTML 标签验证失败，原因是「无法连接到您网站的服务器」。**

日志核实（按 IP 段，不按 UA —— 这个站的访问日志里已多次出现伪造 UA 的扫描器）：
**百度从未连上过**。日志里那几条 `Baiduspider` 全是伪造 UA 的扫描器（IP 属
Google Cloud，在扫 `/.env.old`、`/Dockerfile`）。同期有大量中国 IP 段正常访问，
所以不是站点故障，是**百度到香港服务器的线路**。

已做的两件事：

1. 把两种验证方式的材料都放上去：`<meta name="baidu-site-verification">`（布局
   metadata，`verification.other`）+ `public/baidu_verify_codeva-cEiQhhMSVF.html`
   （内容是 32 位十六进制串，与文件名一致）。**两个都要留在仓库里** ——
   删掉会掉验证。
2. 消除一个我们这边能消除的失败模式：部分校验器请求的是 `http://`，而明文一律
   301 跳 HTTPS，不跟随跳转的校验器会把「被跳转」报成「无法连接」。现在
   `baidu_verify_*.html` 与 `google*.html` 在明文下也直接由应用返回文件。
   **注意实现细节**：server 级 `if` 在 rewrite 阶段执行、早于 location 匹配，
   所以跳转必须从 server 级 `if` 移进 `location /`，例外才生效
   （`/etc/nginx/conf.d/mizhong.conf`，改动前已备份）。

若百度仍报「无法连接」，剩下的路只有：稍后重试 / CNAME 验证（**只能给子域，裸域加
CNAME 会顶掉 A 记录把网站搞挂**）/ 备案 + 境内服务器（根治，成本大）。

### 百度每日自动推送（2026-09-23 配置完成）

**背景**：百度给未备案新站的配额极为克制 —— API 推送 10 条/天、sitemap 提交 0 条/天
（`站点属性 → 主体备案号` 未填写，而服务器在香港**无法备案**，这条路是堵死的）。
所以只能把这 10 条/天用足，且必须自动 —— 手动推 26 天不现实。

| 位置 | 内容 |
| --- | --- |
| `/etc/cron.d/htd-baidu-push` | 每天 **09:23** 跑一次；删掉这个文件即停 |
| `/opt/mizhong/.env.local` | `BAIDU_PUSH_TOKEN=…`（**不在 Git 里**） |
| `/opt/mizhong-data/baidu-push-cursor.txt` | 轮换游标 |
| `/opt/mizhong-data/baidu-push.log` | 每次运行的日志 |

**两个设计决定**：

1. **只推 zh + en，且中文页优先**（`--locales zh,en`，按该顺序重排）。
   sitemap 里每个商品有 11 个语言版本，按原顺序轮换会让同一商品的 11 个语言各占一天；
   百度服务中文搜索，所以先推完 **131 个中文页（≈14 天）**，之后才轮到英文页
   （英文页在客户按型号搜索时有用）。不筛的话要 144 天，且 10 条里只有 1 条中文。
   排序而非阶段切换：不需要额外的状态，轮换游标照旧。
2. **游标只按百度实际接收的条数推进**，接收 0 条就原地不动 —— 保证不会有地址被静默跳过。
   当天试跑（配额已用尽）验证了这条：`{"error":400,"message":"over quota"}` → 游标未创建、
   未推进 ✓。

顺带记下这个坑：**百度推送的 `site` 参数不能做 URL 编码**，编码后报
`{"error":400,"message":"site init fail"}`（文案极具误导性，看着像站点没初始化，
实际是参数形式问题；同一 token、同一批地址，编码后 400、不编码 200）。

## 追加：GSC「应指定 offers、review 或 aggregateRating」（2026-09-24）

GSC 对商品页报了 1 项严重问题：`Product` 缺少 `offers` / `review` / `aggregateRating`。

**这是面议商品的必然结果，不是缺陷。** Google 的商品富媒体结果要求 Product 至少带
三者之一，而我们 129 个商品都没有价格（`PriceMode = NEGOTIABLE`）。提示的性质是
**「不符合富媒体资格」**：页面照常收录、照常参与排名，只是不会出现搜索结果里那种
带价格/评分的卡片。

使它变绿的三条路，两条不能走：

| 做法 | 判断 |
| --- | --- |
| 编一个价格 | ❌ 误导搜索引擎，也误导询价客户 |
| 编一个评分 | ❌ 我们没有评价；伪造结构化数据可能招致人工处置 |
| 去掉 `Product` 标记 | ❌ 丢掉名称/型号/描述/品牌这些实体信号，而「搜型号能找到」正需要它 |
| **接受该提示** | ✅ 面议的 B2B 商品本来就不该出价格卡片 |

代码本来就写对了（只有存在真实数字价格时才输出 `offers`）；本轮补上 Google 推荐的
`brand` 字段（用公司名，各语言各自取值）—— 与品牌实体识别是同一条线。判断与理由写进了
`src/lib/product-jsonld.ts` 的注释块，并用 6 个用例锁住（含「面议不输出 offers」
与「填了价格就出现 offers」两面）。
